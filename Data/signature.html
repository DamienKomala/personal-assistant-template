This signature is installed in your mail client — it is NOT appended to drafts. The Gmail connector strips every <img> tag on save: remote src, cid: inline attachment and data: URI alike. All three were tested together in one draft in the source repo; all three were gone.

So a drafted signature is always image-less and arrives as empty <a></a> shells beside a dangling border — broken rather than plain. Both job-search skills therefore draft with no signature at all, and you add this one at send time.

Gmail web auto-inserts a signature only on a fresh compose, never when opening a prepared draft. Use the compose toolbar's Insert signature control. Two clicks, full signature, images intact.

Rules that are load-bearing




    
  
  • No hardcoded text colors. Recipients read mail in light and dark themes. A hardcoded color:#333 is invisible on a dark background — let the client's default win, and use opacity, borders and spacing for structure instead. The one border above uses a mid grey that reads on both.
    • 
  
  • Never let a <p> be the only thing holding an element in the document. Third-party clients strip every <p> and flatten the body into one <div>. In the source repo the headshot was the single signature image whose sole parent was a <p> — the other three sat inside <a href> anchors and survived. Anchoring the image fixed it. That is why the <img> above is wrapped in a link.
    • 
  
  • Tables, not flexbox. Mail clients are not browsers. display:flex, grid and external stylesheets do not survive; a cellspacing="0" table with inline styles does.
    • 
  
  • Lead with the link you most want clicked — and keep social.md in the same order.
    • 
  
  • Host the headshot somewhere permanent. A data: URI bloats every message and some clients reject it; a link to a file that later moves leaves a broken image on every email you ever sent.
    • 
  
  • There is no settings API on any of these connectors. Installing a signature is a manual paste, once per client. Re-paste after any edit here.
